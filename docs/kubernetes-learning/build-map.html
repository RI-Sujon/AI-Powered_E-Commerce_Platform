The journey

The solid arrows are the order things were built. The two dotted arrows are the interesting part: K2 surfaced two real problems while building the storage layer, and each one became the reason a later phase exists.

What's actually running right now

This is the live request path today — the original ecommerce namespace from K1–K4, still up. K5's dev/staging/prod overlays exist as manifests but aren't currently deployed (see the callout below).

K5's actual mechanism: patch, don't copy

The part of K5 that's easy to misread as "three copies of the app." It's the opposite: one shared base, and each overlay only states the handful of fields that make it different.

Yes — it's live and usable right now

  • All 4 Pods in the ecommerce namespace: Running
  • Ingress controller: Running, reachable at http://localhost
  • Open http://localhost/Product in a browser right now — full page, and its API calls succeed through the Ingress (the K4 fix)

Not live: the K5 dev/staging/prod overlays. prod was applied, verified, then deliberately torn down to keep load off the machine — re-running kubectl apply -k k8s/overlays/prod brings it back in under a minute.

One environment quirk worth knowing: Docker Desktop on this machine has hung a few times across these phases, traced each time to a stale WSL VM process left over between sessions. If the cluster's ever unreachable, wsl --shutdown then relaunching Docker Desktop has fixed it every time.
